## 为什么归档

项目一度有 **8 份互相重叠的状态/交接文档**，且它们对同一个量给出过不同数值——
其中一次（论文 Table 1 的 `final` 列）**把两个不同口径的数混进了同一张表**。
根因是：手工维护的状态文档会腐烂。

替代方案是 **[`../STATUS.md`](../STATUS.md)**：它的**实测部分由脚本从 `results/*.json`
直接生成**（`python scripts/build_status.py`），所以不可能与数据脱节；
它同时做**证据纪律检查**（同一量在不同 JSON 里不一致时报警）。

## 一条纪律（归档的原因值得记住）

> **凡是"分成两组""普遍成立""机制上说明"这类说法，先做两件事**：
> (a) 列出每个成员的具体值，看分组是否真分得开；
> (b) 在该主张**所属的那个数据集/模型**上再测一遍，而不是拿邻近设置的结果替代。
>
> 这条写在 `STATUS.md` §9 第 6 条。本项目在一天之内犯过两次同类错误
> （把单数据集结果写成普遍结论、把重叠的两组写成"分裂"），两次都不是算错，
> 而是**归纳跨度超过了测量范围**。
